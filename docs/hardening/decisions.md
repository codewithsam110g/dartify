# Hardening decisions

IDs are `HD-NN`, append-only, same rules as [../decisions.md](../decisions.md). A decision proposed but not yet agreed lives in
[pending.md](pending.md) under the number it will keep.

HD-02–HD-12 were agreed with the user at the intake of the `17e8aa9` release audits (2026-11-05). Each governs the
findings named in it; the brief that fixes them implements the decision and may not reopen it without a superseding HD.

| ID | Decision | Date | Ref |
|----|----------|------|-----|
| HD-01 | The gate keeps its own decisions, register and briefs in `docs/hardening/`; the baseline commit is recorded in names, not as a git tag. Imported audits keep **documents only**: reproducers, probes, evidence scripts and logs of the two `17e8aa9` audits were untracked at D3 adoption and stay in the git-ignored `/audit/` (and in git history up to `c46a128`); each HG fix turns its reproducer into a test. | 2026-11-05 | |
| HD-02 | **TS `Date` binds to a generated JS-interop class for the JavaScript `Date`** (core members such as `getTime()`, `toISOString()`, plus `toDateTime()` and a `fromDateTime()` factory), never to Dart `DateTime` (`CA-01` = `DAR-012`). js_facade_gen maps `'Date': 'DateTime'` (`lib/dart_libraries_for_browser_types.ts:955`), which only worked under Dartium's automatic `dart:js` conversion; `package:js` under dart2js has never converted `Date` (dart-lang/sdk #14443, #25886, #28329), and `dart:js_interop` forbids `DateTime` in external signatures, so the same shape carries to v2. A deliberate departure from js_facade_gen under D-31, recorded in the conformance ledger if a case covers it. The class name and member set are settled in the HG-4 brief. | 2026-11-05 | D-31, [findings](findings.md) |
| HD-03 | *Superseded by HD-13* (the per-file write clause conflicted with the all-or-nothing write rule of task 4.11). **TypeScript syntax errors in an input file are errors** (`DAR-001`, `CA-10`): each is reported with `file:line`, **no output is written for that file** (other files still emit), and the run **exits 1** — the same contract `transpileFromString` already has. Error recovery never produces bindings. | 2026-11-05 | D-09 |
| HD-04 | **Every explicit input must be a readable declaration file** (`DAR-002`, `CA-14`): a missing, unreadable or directory `-d` path is a named error and the run exits 1, even when other inputs are fine. `.d.mts` and `.d.cts` are accepted as declaration inputs. | 2026-11-05 | D-08, D-09 |
| HD-05 | **Ambient `declare module "<specifier>"` bindings** (`CA-06`): `--js-root` applies to them as it does to module files. Without a root, a specifier that is not a valid JavaScript property path gets an explicit diagnostic and is **never** emitted as an `@JS("<specifier>.<name>")` path (which crashes dart2js). | 2026-11-05 | D-09 |
| HD-06 | **Global declarations merged across files are supported** (`CA-07`): the linker merges them into one class (D-12), owned by the first declaring file in the deterministic input order; other files import it. No partial duplicate classes and no `dynamic` use sites. | 2026-11-05 | D-12 |
| HD-07 | *Refined by HD-14.* **Command-line compatibility with js_facade_gen is best effort, decided by the planner** (`CA-30`), per D-31: accept the common invocation shapes (positional input files, `--destination` as an alias of `-o`); reject unknown flags; js_facade_gen flags dartify does not implement fail with a clear message naming the replacement where one exists — never silently accepted. | 2026-11-05 | D-31 |
| HD-08 | **CI pins the exact Dart SDK the analyzer baseline was taken with** (`CA-17`); the SDK and `test/dart/baseline.json` are bumped together in one change. | 2026-11-05 | D-14 |
| HD-09 | **Watch latency claims are corrected to measured numbers** (`CA-27`), including the worst measured cases (Leaflet leaf ~205 ms, three.js core ~909 ms); no performance work before `1.0.0`. `pnpm bench` stays the source of the numbers. | 2026-11-05 | |
| HD-10 | **`browserTypes.ts` gets a committed validator** in `tools/` that checks every entry against the Dart SDK (`CA-29`); a generator is added if the original port can be reconstructed. *Refines D-22* ("regenerate and re-validate" now names the tool). | 2026-11-05 | D-22 |
| HD-11 | **Construct signatures on type-only interfaces** (`CA-31`) get an explicit unsupported diagnostic, and such an interface is no longer marked `@anonymous`. | 2026-11-05 | D-09 |
| HD-12 | **Dependency advisories** (`CA-19`, `CA-20`): upgrade to patched versions first, then `pnpm.overrides` for transitive ones; any advisory left is recorded with its reason and reach. | 2026-11-05 | |
| HD-13 | *Refined by HD-16.* **Supersedes HD-03. Syntax errors follow the all-or-nothing write rule** (`DAR-001`, `CA-10`): TypeScript **syntactic** diagnostics of every file dartify parses for symbols (inputs and the dependency files it generates from) are generation failures — each reported with `file:line:column` and its `TSnnnn` code, **nothing is written**, and the run exits 1, exactly like every other generation failure (task 4.11, `src/transpiler.ts` `transpile()`; watch mode already writes nothing on failure). Recovery output never reaches disk. Type-check (semantic) diagnostics stay non-fatal: unresolved names degrade to named typedefs (D-10) and are reported by the link report. | 2026-11-05 | D-09, D-10 |
| HD-14 | *Refined by HD-15.* **js_facade_gen invocation mapping** (the planner's choice under HD-07, `CA-30`): positional arguments are input files/globs, equivalent to `-d`; `--destination` is an alias of `-o`; `--base-path` overrides the input root that output paths are relative to (every input must lie under it, else an error); with positional inputs and no `-o`/`--destination`, a run that yields exactly one library prints it to stdout (logs to stderr), as js_facade_gen's basic usage did, and a multi-library result is an error asking for `--destination`. `--skip-formatting` is accepted as a no-op (dartify never runs a formatter). `--generate-html`, `--rename-conflicting-types`, `--explicit-static` and `--trust-js-types` exit 1 with a message stating what dartify does instead. Unknown flags are rejected (`yargs` strict mode). Without positional inputs, today's behaviour (`-o` default `./dart_out`) is unchanged. | 2026-11-05 | D-31 |
| HD-15 | **Refines HD-14: CLI details settled in HG-2** (agreed 2026-11-06). `--watch` in stdout mode (positional inputs, no `-o`/`--destination`) is a usage error asking for `-o`/`--destination`: a rebuild loop cannot print one library, and silently writing `./dart_out` would hide where output went. Giving the output directory (`-o`/`--output`/`--destination`) or `--base-path` more than once is a usage error, not a silent pick. A leading `!` makes an argument a negation glob, so `-d "**/*.d.ts" -d "!x.d.ts"` works. Each refused js_facade_gen flag's one-line message states what dartify does, read off the code (`src/cliOptions.ts`). Other output collisions among `.d.ts`/`.d.mts`/`.d.cts` inputs stay errors (HD-04); the `.d.mts`+`.d.cts`-without-`.d.ts` case is tracked as risk `RS-01` in [../issues.md](../issues.md). | 2026-11-06 | HD-04, HD-14 |
| HD-16 | **Refines HD-13: scope and reporting of syntax failures** (agreed 2026-11-06). Dependency declaration files dartify generates from, including typings under `node_modules`, are in scope: a syntax error there fails the run like one in an input. Accepted trade-off: typings written in syntax newer than the TypeScript bundled with ts-morph stop the run where they were silently accepted before (risk `RS-02`, mitigated by keeping ts-morph current; h3-js, leaflet and three parse cleanly). A failing build prints every failure (`TranspileException.diagnostics` carries them all) and only the failures: its link and emission counts describe a recovered program, so they are not printed, in one-shot and watch mode alike. | 2026-11-06 | HD-13, D-10 |
