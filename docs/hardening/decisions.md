# Hardening decisions

IDs are `HD-NN`, append-only, same rules as [../decisions.md](../decisions.md). A decision proposed but not yet agreed lives in
[pending.md](pending.md) under the number it will keep.

HD-02–HD-12 were agreed with the user at the intake of the `17e8aa9` release audits (2026-11-05). Each governs the
findings named in it; the brief that fixes them implements the decision and may not reopen it without a superseding HD.

| ID | Decision | Date | Ref |
|----|----------|------|-----|
| HD-01 | The gate keeps its own decisions, register and briefs in `docs/hardening/`; the baseline commit is recorded in names, not as a git tag. Imported audits keep **documents only**: reproducers, probes, evidence scripts and logs of the two `17e8aa9` audits were untracked at D3 adoption and stay in the git-ignored `/audit/` (and in git history up to `c46a128`); each HG fix turns its reproducer into a test. | 2026-11-05 | |
| HD-02 | **TS `Date` binds to a generated JS-interop class for the JavaScript `Date`** (core members such as `getTime()`, `toISOString()`, plus `toDateTime()` and a `fromDateTime()` factory), never to Dart `DateTime` (`CA-01` = `DAR-012`). js_facade_gen maps `'Date': 'DateTime'` (`lib/dart_libraries_for_browser_types.ts:955`), which only worked under Dartium's automatic `dart:js` conversion; `package:js` under dart2js has never converted `Date` (dart-lang/sdk #14443, #25886, #28329), and `dart:js_interop` forbids `DateTime` in external signatures, so the same shape carries to v2. A deliberate departure from js_facade_gen under D-31, recorded in the conformance ledger if a case covers it. The class name and member set are settled in the HG-4 brief. | 2026-11-05 | D-31, [findings](findings.md) |
| HD-03 | **TypeScript syntax errors in an input file are errors** (`DAR-001`, `CA-10`): each is reported with `file:line`, **no output is written for that file** (other files still emit), and the run **exits 1** — the same contract `transpileFromString` already has. Error recovery never produces bindings. | 2026-11-05 | D-09 |
| HD-04 | **Every explicit input must be a readable declaration file** (`DAR-002`, `CA-14`): a missing, unreadable or directory `-d` path is a named error and the run exits 1, even when other inputs are fine. `.d.mts` and `.d.cts` are accepted as declaration inputs. | 2026-11-05 | D-08, D-09 |
| HD-05 | **Ambient `declare module "<specifier>"` bindings** (`CA-06`): `--js-root` applies to them as it does to module files. Without a root, a specifier that is not a valid JavaScript property path gets an explicit diagnostic and is **never** emitted as an `@JS("<specifier>.<name>")` path (which crashes dart2js). | 2026-11-05 | D-09 |
| HD-06 | **Global declarations merged across files are supported** (`CA-07`): the linker merges them into one class (D-12), owned by the first declaring file in the deterministic input order; other files import it. No partial duplicate classes and no `dynamic` use sites. | 2026-11-05 | D-12 |
| HD-07 | **Command-line compatibility with js_facade_gen is best effort, decided by the planner** (`CA-30`), per D-31: accept the common invocation shapes (positional input files, `--destination` as an alias of `-o`); reject unknown flags; js_facade_gen flags dartify does not implement fail with a clear message naming the replacement where one exists — never silently accepted. | 2026-11-05 | D-31 |
| HD-08 | **CI pins the exact Dart SDK the analyzer baseline was taken with** (`CA-17`); the SDK and `test/dart/baseline.json` are bumped together in one change. | 2026-11-05 | D-14 |
| HD-09 | **Watch latency claims are corrected to measured numbers** (`CA-27`), including the worst measured cases (Leaflet leaf ~205 ms, three.js core ~909 ms); no performance work before `1.0.0`. `pnpm bench` stays the source of the numbers. | 2026-11-05 | |
| HD-10 | **`browserTypes.ts` gets a committed validator** in `tools/` that checks every entry against the Dart SDK (`CA-29`); a generator is added if the original port can be reconstructed. *Refines D-22* ("regenerate and re-validate" now names the tool). | 2026-11-05 | D-22 |
| HD-11 | **Construct signatures on type-only interfaces** (`CA-31`) get an explicit unsupported diagnostic, and such an interface is no longer marked `@anonymous`. | 2026-11-05 | D-09 |
| HD-12 | **Dependency advisories** (`CA-19`, `CA-20`): upgrade to patched versions first, then `pnpm.overrides` for transitive ones; any advisory left is recorded with its reason and reach. | 2026-11-05 | |
